## 2026-10-18 W2 decision
- Clone without `--filter=blob:none`: on Calva a partial clone fetched blobs one commit at a time (2 min per 200 commits for `git log -p`); a shallow clone with blobs (depth 2000) took 42 s and history reads take under a second. Command: `git clone --no-tags --single-branch --depth <d> [--branch <b>]`; updates `git fetch --depth <d> origin +refs/heads/<b>:refs/remotes/origin/<b>` then checkout/reset.
- Merge commits: recorded with `isMerge` and parents, no file changes (no `-m`); their changes come through the merged commits. Shallow-boundary commits are recorded without file changes.
- `GitFileChange.hunks` is stored as `"start-end"` strings: the loader only allows arrays of scalars, so `[start, end]` pairs are rejected.
- Qualified names: Java is dotted inside the file (`Outer.Inner.method`, package kept for resolution only); Rust methods `Type::method`, inline modules `mod::name`; TS/JS test callbacks `describe > it`; Go methods `Recv.Method`.
- `CALLS.resolution` uses only the ontology values (local, import, project, name_only); the self/cls tier is stored as `local` with confidence 0.95. `CALLS.method` is `structural` for local/import and `inferred` for project/name_only.
- Unresolved calls = ambiguous name-only matches plus bare-name calls in tier-1 languages that match nothing and are not builtins. Calls on unknown receivers that match no repo name are treated as library calls (not counted).
